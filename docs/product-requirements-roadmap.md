## 1. 文档目的

本文档是项目后续开发的唯一主路线图，用来回答五个问题：

1. 产品最终要解决什么问题；
2. 当前已经可靠实现了什么；
3. 仍缺少哪些用户功能和生产能力；
4. 图片修复与视频插帧分别如何落地；
5. 应按什么依赖关系和验收门槛推进。

`docs/requirements-status.md` 保留为简明状态表；技术细节仍分别记录在模型、
文件系统和开发流程文档中。若各文档对产品范围或优先级的描述冲突，以本文档为准。

## 2. 需求来源与待确认假设

### 2.1 已确认需求

- 使用 RK3588 本地 NPU 完成推理，不依赖云端 GPU；
- 用户通过网页上传媒体并下载结果；
- 服务可通过 Cloudflare 域名从公网访问；
- 项目文件、模型、用户数据、临时数据和其他板端项目必须隔离；
- 首个图片模型为 Real-ESRGAN x4plus FP16 RKNN；
- 图片公网输入上限保持 2,000,000 像素，除非运行时/驱动和稳定性重新验证；
- 视频方向优先研究类似“游戏插帧”的帧率提升，而不是逐帧运行
  Real-ESRGAN；
- 所有重要流程应可重复执行、可检查、可清理，并主动保留 Git 提交记录。

### 2.2 当前产品假设

以下内容作为现阶段设计假设，后续可由产品决策修改：

- 这是单台 RK3588 的个人/小规模共享服务，不是多节点商业云平台；
- Cloudflare Access 是公网入口的第一层身份认证；
- NPU 同一时间只执行一个重型任务；
- 图片和视频都采用异步任务，而不是要求浏览器连接持续在线；
- 视频首版是离线处理，不承诺实时游戏捕获、实时直播或 1080p60 实时生成；
- 默认重视稳定、隐私和可恢复性，优先级高于极限画质和峰值吞吐量；
- 用户原始文件只在声明的保留期内保存，且不得进入 Git。

### 2.3 后续需要明确的产品决策

- 服务只允许本人使用，还是允许多个 Cloudflare Access 用户使用；
- 多用户是否能看见彼此的任务；默认方案为严格隔离；
- 照片功能优先级：人脸修复、划痕修复、去噪去模糊、上色，哪项优先；
- 视频更重视动漫、真人、老录像还是游戏录屏；
- 视频结果默认 H.264 还是 H.265；
- 用户文件默认保留 24 小时、7 天，还是完成下载后立即删除；
- 是否需要管理员后台、邮件/消息告警和长期性能图表。

这些决策未确认时，开发应采用本文档中风险最低、最易回退的默认值。

## 3. 产品愿景

将 RK3588 建成一台可通过局域网或受保护公网访问的本地 AI 媒体增强工作站：

- 照片：放大、增强清晰度，并逐步加入人脸、划痕、噪声、模糊和上色修复；
- 视频：优先提供 2 倍帧率的离线智能插帧，后续再评估时序视频超分；
- 平台：统一上传、排队、进度、预览、下载、历史记录、清理和健康监控；
- 运维：即使 SSH 中断、服务重启或单个任务失败，也不破坏其他任务和板端项目；
- 隐私：媒体文件留在自有设备，公网入口受到身份、配额和限流保护。

## 4. 成功标准

### 4.1 用户价值

- 用户不用 SSH 或 PowerShell 就能完成日常图片/视频处理；
- 上传后可以关闭网页，稍后回来查看进度和下载结果；
- 用户能明确知道文件限制、预计等待、失败原因和保留期限；
- 输出不改变原文件，下载文件具有清晰、稳定的命名；
- 视频插帧在运动区域、场景切换和音画同步方面达到可用水平。

### 4.2 工程质量

- 每个发布版本都有自动化测试、部署检查、冒烟测试和回滚方式；
- API、Worker、模型和数据库版本可追踪；
- 任何用户输入都不能越过项目目录、执行命令或读取其他任务；
- NPU 任务串行、有超时和心跳，卡住时停止接收新任务并给出明确告警；
- 已完成/失败任务可按保留期和磁盘配额安全回收；
- 关键实测结果写入报告，不以主观感觉替代稳定性结论。

### 4.3 目前不承诺的指标

- 不承诺实时视频插帧；
- 不承诺 4K 视频或任意长度视频；
- 不承诺 3 MP 以上图片；
- 不承诺消费级显卡上的 DLSS/FSR 等价效果；
- 在完成模型和板端基准前，不公布视频处理速度。

## 5. 当前已验证基线

### 5.1 模型与图片 Worker

- Real-ESRGAN x4plus，FP16，固定 `1×3×96×96` 输入；
- 每边 8 输入像素 overlap，4 倍输出；
- PTH → ONNX → RKNN 构建可复现，并有 SHA-256；
- RKNN/ONNX 最大绝对误差低于 0.01，平均绝对误差低于 0.001；
- 支持 EXIF 方向、RGB 转换、padding、tiling、overlap-add 和裁剪；
- 支持内存与磁盘合成器；
- 支持 PNG/JPEG、完整输出、1600 像素最长边预览和 JSON 报告。

### 5.2 已测性能和安全边界

| 输入 | 结果 | NPU/总耗时 | 峰值 RSS | 结论 |
|---|---|---:|---:|---|
| 1280×720 | 通过 | 63.678 / 74.681 秒 | 470,232 KiB | 稳定 |
| 1920×1000 | 通过 | 137.156 / 158.146 秒 | 622,344 KiB | 当前公网上限内 |
| 2000×1500 | 失败 | 第 211/475 tile 后停滞 | 约 609 MiB | NPU 驱动卡死，需重启 |

3 MP 失败不是内存、磁盘或温度耗尽。当前 RKNN Runtime 2.3.2 / Driver 0.9.2
下不得把公网图片上限提高到 3 MP。

### 5.3 已部署平台

- FastAPI 0.5.0、SQLite 单 Worker 队列和静态 Web UI；
- systemd 自启动和 `Restart=always`；
- Cloudflare Tunnel + Cloudflare Access 公网入口；
- 任务历史、输入/输出/报告下载和终止态任务删除；
- 7 天终止态任务保留、4 GiB 任务配额、2 GiB 磁盘保留；
- Worker/清理线程、任务状态、疑似停滞、磁盘、NPU、温度和服务健康检查；
- 单图 CLI、验证集批处理、断线恢复和 API 图片冒烟测试。

### 5.4 当前已知技术债

- `FastAPI.on_event` 已弃用，后续应迁移到 lifespan；
- SQLite 表结构使用启动时增列，没有正式迁移版本；
- 服务启动会把所有 `RUNNING` 任务直接改回 `QUEUED`，缺少按任务类型和现场状态
  的恢复策略；
- Worker 使用单进程 `subprocess.run`，没有细粒度进度心跳和安全取消协议；
- NPU 驱动进入不可中断状态后，SIGTERM/SIGKILL 无法恢复，只能重启板子；
- README 和文件系统文档中的部分“future”描述已经过时；
- 应用当前没有用户所有权字段，所有授权用户共享任务列表。

## 6. 功能需求总览

状态定义：

- `DONE`：实现并在目标设备验收；
- `PARTIAL`：已有基础能力，但不满足完整产品要求；
- `PLANNED`：已进入路线图；
- `RESEARCH`：必须先通过技术可行性门槛；
- `GATED`：实现意图明确，但必须先通过指定的安全或稳定性门槛；
- `BLOCKED`：已有证据表明当前环境不能安全实现，等待外部条件变化；
- `DEFERRED`：明确暂缓，不应阻塞近期版本。

表格中的 `DONE/扩展视频`、`DONE for Real-ESRGAN` 等组合写法表示已有能力在当前
图片或指定模型范围内完成，但扩展到新媒体/模型仍需重新验收，不能自动继承状态。

优先级定义：

- `P0`：生产安全或数据正确性，必须先做；
- `P1`：下一阶段核心用户价值；
- `P2`：重要增强；
- `P3`：长期探索。

### 6.3 视频智能插帧

#### 6.3.1 产品定义

视频首版目标是离线 2× 插帧：读取相邻原始帧，估计运动并生成中间帧，将
24/25/30 FPS 转为 48/50/60 FPS，保持原分辨率并保留音频。

这不是直接复制游戏 DLSS/FSR：普通视频没有游戏引擎提供的深度、运动矢量、
抖动采样和渲染上下文。首版也不是逐帧 Real-ESRGAN；空间超分与时间插帧是两条
独立模型链路。

#### 6.3.3 首版建议限制

技术预检完成前不把这些数值写成永久承诺。第一轮原型建议：

- 容器：MP4；视频：H.264 8-bit 4:2:0；
- 输入：先 640×360，再验证最高 1280×720；
- 时长：10 秒夹具，稳定后扩至 30 秒；
- 倍率：只做 2×；
- 音频：AAC 直通优先；
- 任务：一次只运行一个视频 NPU 任务；
- 访问：先 CLI/开发接口，再内网页面，最后才考虑公网。

#### 6.3.4 视频可行性否决门槛

出现以下任一情况时，不得直接进入产品集成：

- 核心 warp/grid/sample 类算子无法正确转换，且替换会显著改变模型；
- RKNN 与参考输出差异造成可见重影、撕裂或边缘错误；
- 720p 必须依赖不可控的超大内存复制；
- 连续短视频测试导致 NPU 100% 卡死且进程/服务无法恢复；
- 场景切换、时间戳或音频同步没有可靠策略；
- 模型或训练数据许可不允许本项目的部署方式。

若轻量神经网络插帧未通过，应保留标准 FFmpeg 流程，并评估 RIFE 的 CPU/GPU
离线回退或传统运动补偿，但不能把回退路径宣传成 NPU 智能插帧。

### 6.10 测试与发布质量

每个版本至少包含以下层次：

1. **静态检查**：Python、PowerShell、Shell、JavaScript 语法和 `git diff --check`；
2. **单元测试**：状态机、路径边界、配额、清理、恢复、媒体参数；
3. **模型测试**：ONNX/RKNN 数值差异、shape、输入输出范围；
4. **板端集成**：实际 NPU、硬件编解码、内存、温度和磁盘；
5. **API 冒烟**：上传 → 排队 → 处理 → 预览 → 下载 → 删除；
6. **故障注入**：SSH 断开、API 重启、磁盘不足、非法文件、任务取消；
7. **稳定性**：重复任务、长时间空闲、连续处理和板子重启；
8. **安全测试**：跨用户访问、路径穿越、伪造 Header、超限和速率限制；
9. **视觉验收**：固定原图/视频、局部放大、切镜、遮挡、文字和人脸；
10. **回滚验收**：新版本失败后恢复旧服务、数据库和模型。

视频质量报告至少记录：输入/输出 codec、分辨率、帧率、帧数、时长、音频流、
处理速度、峰值 RSS、温度、模型 hash、场景切换数和失败帧数。PSNR/SSIM/LPIPS
等指标仅作参考，必须配合时序稳定性和人工观看。

```text
Browser
  │
  ▼
Cloudflare Access + Tunnel
  │  verified identity
  ▼
FastAPI / Web UI
  ├── media validation
  ├── ownership / quota / rate limit
  ├── SQLite metadata + migrations
  └── job scheduler (single NPU lane)
          │
          ├── Image pipeline
          │     Real-ESRGAN / future restoration stages
          │
          └── Video pipeline
                ffprobe → decode → scene detect
                → RKNN interpolation → encode → audio mux

Storage
  ├── jobs/<owner>/<job-id>/
  ├── previews/
  ├── reports/
  ├── tmp/               bounded and recoverable
  └── database backups/

Operations
  ├── systemd services
  ├── health + metrics + logs
  ├── atomic deploy / rollback
  └── retention / quota / backup
```

图片与视频可以使用不同 Worker，但必须共享任务状态、身份、存储预算和 NPU 调度，
避免各自实现一套互相冲突的队列。

### 7.1 统一任务状态机

建议状态转换如下：

```text
UPLOADING ──成功──> QUEUED ──调度──> RUNNING ──成功──> COMPLETE
    │                  │                 │
    ├──失败──> REJECTED│                 ├──可恢复错误──> FAILED
    │                  └──取消──> CANCELLED
    └──连接中断/超时清理                  ├──取消请求──> CANCELLING
                                       │                 └──> CANCELLED
                                       └──心跳超时──> STALLED
```

实现时可将 `UPLOADING/REJECTED/CANCELLING/STALLED` 作为正式状态或“状态 + 原因”，
但 API 和数据库必须保持一致。规则如下：

- 只有完成校验和空间预留的文件才能进入 `QUEUED`；
- 每次状态转换都原子更新 `updated_at`、阶段、进度和事件记录；
- `COMPLETE/FAILED/CANCELLED/REJECTED` 是终止态，可被保留策略回收；
- `QUEUED` 取消不能启动 Worker；
- `RUNNING` 取消先进入 `CANCELLING`，Worker 确认安全停止后才标记 `CANCELLED`；
- 心跳超时不能直接假定进程已死或自动重跑，应进入 `STALLED`/告警并保留现场；
- 服务重启后，按任务类型、阶段、心跳和产物完整性决定恢复、失败或重新排队；
- 客户端重复请求必须通过请求 ID 或上传 hash 策略避免意外重复，用户明确要求重复
  处理时仍应允许创建新任务。

### 7.2 概念数据模型

后续 schema 至少应覆盖以下实体；字段名称可在迁移设计中调整。

**User / Principal**

- 稳定的内部 `owner_id`；
- Cloudflare Access 身份映射和首次/最后访问时间；
- 角色（user/admin）、启用状态和额度策略；
- 不把原始 Access token 存入数据库。

**Job**

- `id`、`owner_id`、`job_type`、`state`、`stage`；
- `progress_current`、`progress_total`、`progress_unit`、`eta_seconds`；
- `created/queued/started/heartbeat/finished/expires` 时间；
- 原始文件名、安全显示名、媒体类型、输入/output/report/preview 逻辑引用；
- 输入/output SHA-256、字节数、宽高、帧率、帧数、时长、codec、音频信息；
- 处理参数、模型 ID/hash、Worker/API 版本；
- 公开错误码/消息和内部诊断引用；
- `client_request_id`、取消请求时间和清理时间。

**Artifact**

- `job_id`、类型（input/output/preview/report/log/work）；
- 相对路径、大小、SHA-256、媒体类型、创建/过期时间；
- 路径必须由服务端根据任务目录生成，不能接受客户端提供的绝对路径。

**Job Event / Audit**

- 状态转换、操作者、时间、原因和版本；
- 不存储原始媒体内容、Access token 或完整敏感 Header；
- 用户删除、自动回收、管理员操作和恢复动作可追踪。

**Model Manifest**

- 模型 ID、用途、版本、来源、许可证、源/ONNX/RKNN hash；
- 固定输入输出、精度、目标平台、工具链版本和验收报告引用。

SQLite 仍适合单板首版，不需要为了视频立即引入外部数据库。重点是正式 schema 版本、
事务边界、备份和迁移，而不是更换数据库品牌。

### 7.3 目标 API 边界

现有 `/api/jobs` 可在兼容期保留，后续建议形成版本化接口：

| 方法与路径（示意） | 用途 | 关键要求 |
|---|---|---|
| `GET /api/v1/capabilities` | 支持格式、模式、限制和模型状态 | 前端不得硬编码全部限制 |
| `GET /api/v1/health` | 公开的最小就绪状态 | 不泄露内部路径和敏感诊断 |
| `GET /api/v1/jobs` | 当前用户任务列表 | 强制 owner 过滤、分页和上限 |
| `POST /api/v1/jobs` | 创建图片/视频任务 | 身份、限流、幂等 ID、预检、空间预留 |
| `GET /api/v1/jobs/{id}` | 状态、阶段、进度和结果链接 | 强制所有权 |
| `POST /api/v1/jobs/{id}/cancel` | 请求取消 | 与删除分离，状态转换原子化 |
| `DELETE /api/v1/jobs/{id}` | 删除终止任务全部产物 | 二次确认、所有权和审计 |
| `GET /api/v1/jobs/{id}/artifacts/{kind}` | 预览/下载 | 私有缓存策略、文件存在和 hash 检查 |
| `GET /api/v1/admin/health` | 深度诊断 | 仅管理员，可看队列/NPU/磁盘但默认不看媒体 |

接口要求：

- 错误使用稳定的机器错误码和本地化显示消息；
- 不把数据库行、绝对路径、命令、traceback 或 Worker stderr 直接返回；
- 列表必须分页，不能因任务增长读取全部记录；
- 下载应支持合理的缓存、断点或范围请求策略，视频尤其需要验证；
- 所有修改类请求应记录 request/correlation ID；
- 健康检查与用户任务查询分离，避免边缘监控产生大量数据库负载；
- 管理端接口不能仅依赖前端隐藏按钮。

### 7.4 媒体生命周期

```text
客户端选择文件
  → 浏览器提示本地限制
  → 服务端流式上传到隔离临时文件
  → 内容探测、hash、媒体参数和空间预算
  → 原子激活任务输入并入队
  → Worker 产生 work/preview/output/report
  → 校验输出后标记 COMPLETE
  → 用户预览/下载
  → 用户删除或保留期/配额清理
  → 删除产物、数据库终止记录按审计策略保留或匿名化
```

隐私和正确性要求：

- 上传失败或校验拒绝必须清理临时文件；
- 输入文件默认只读，Worker 不在原路径原地改写；
- 所有最终产物使用临时文件 + 原子 rename 激活；
- 输出未通过媒体探测/hash/完整性检查前不能标记完成；
- 预览是独立衍生物，删除任务时必须一起删除；
- 日志只记录任务 ID、阶段和必要技术信息，不记录完整文件内容；
- 对外明确文件保留时间，并允许用户提前删除；
- 数据库备份的保留策略必须考虑其中可能含有文件名和身份标识。

目标：在增加视频这种重任务前，确保数据、身份和部署可以恢复。

依次实现：

1. 正式数据库 schema 版本和迁移框架；
2. 部署前 SQLite/配置备份及恢复验证；
3. 原子版本部署、健康检查和一键回滚；
4. 任务所有者字段与 Cloudflare Access 身份验证；
5. 用户任务隔离、用户配额和速率限制；
6. 明确任务状态机、幂等请求 ID、取消语义；
7. Worker 心跳、分阶段进度和安全重启恢复；
8. 日志轮转、敏感信息过滤和灾难恢复文档；
9. 建立有界保留的运行指标采集，先生成机器可读历史报告，再提供管理员趋势图表。

完成门槛：第二个测试用户不能读取第一个用户的任务；部署失败可回滚；数据库可从
备份恢复；排队任务可取消；服务重启不会盲目重复已完成的重型阶段。
至少保留一段可配置周期的聚合运行数据，并能查看处理耗时、队列、失败率、NPU、
温度、内存和磁盘趋势；指标中不得包含原始媒体、文件内容或 Access token。

### 阶段 2：视频能力技术预检（隔离研发，不接公网）

目标：尽早回答 RK3588 是否适合当前设想，避免先写完整网页再发现模型不可用。

依次实现：

1. `video-preflight` 只读审计：FFmpeg、ffprobe、MPP、RGA、编码器、解码器、磁盘；
2. 建立 3～6 个短视频夹具及许可证 manifest；
3. 选取两个轻量插帧候选，检查模型许可和 ONNX 算子；
4. 先用固定小 shape 生成 ONNX 参考输出；
5. 转换 RKNN，做数值验证和单次推理；
6. 运行 640×360 的完整 10 秒视频链路；
7. 验证场景切换、时间戳、音频 remux、异常清理；
8. 再测试 720p、30 秒和连续三次稳定运行；
9. 形成 Go / Conditional Go / No-Go 决策报告。

完成门槛：不是“模型编译成功”，而是完整短视频三次通过、无 NPU 卡死、输出可播放、
帧数/时长/音频正确，且画面没有不可接受的切镜混合或运动伪影。

### 阶段 3：现有图片产品补全

目标：让“照片修复工作站”不再只有一个固定 4× 超分按钮。

依次实现：

1. 1×增强、2×、4×输出与 PNG/JPEG 选项；
2. 质量预设、预计耗时和更明确的模型能力说明；
3. 图片专项回归集：人脸、文字、细线、纹理、接缝、黑白和低质量 JPEG；
4. 研究并选择人脸修复模型；
5. 研究去噪/去模糊；
6. 再评估划痕/缺损和上色，避免一次串联过多生成模型；
7. 每个功能均可独立开关，支持对比和回退。

完成门槛：每种模式有明确输入范围、模型、速度、质量证据和失败策略；不能仅凭几张
好看的示例上线。

### 阶段 4：视频插帧 MVP 集成

前提：阶段 1 完成，阶段 2 得出 Go 或有明确限制的 Conditional Go。

依次实现：

1. 数据库增加 `job_type=video_interpolation` 及媒体元数据；
2. 视频上传预检和空间预算；
3. 视频 Worker、心跳、阶段进度、取消和失败清理；
4. 与图片任务共享单 NPU 调度；
5. 视频轻量预览、播放器、下载和报告；
6. 先仅内网或管理员开放；
7. 连续稳定性、重启恢复和保留策略验收；
8. 最后才在 Cloudflare Access 后向普通用户开放。

MVP 完成门槛：在公布的分辨率、codec 和时长限制内，用户无需命令行即可可靠完成
上传、2× 插帧、预览和下载；失败不会卡住整个服务或泄露其他用户任务。

### 阶段 5：性能与质量优化

- 测试不同固定 shape、分块/重叠和 RKNN core 配置；
- 在质量允许的前提下评估 INT8/混合精度；
- 优化 decode → inference → encode 的复制和流水线；
- 根据实测决定 720p 上限、最大时长和并发策略；
- 针对动漫、真人、老录像或游戏录屏建立预设；
- 评估模型热切换和图片/视频任务的公平调度；
- 只有驱动和恢复机制改善后，才重新测试 3 MP 图片或更长视频。

### 阶段 6：高级能力（长期）

- 时序视频超分，而非简单逐帧 Real-ESRGAN；
- 插帧 + 视频超分的组合管线；
- 手工蒙版的划痕/缺损修复；
- 批量任务和可下载归档；
- 管理员统计、告警和长期性能趋势；
- 多设备 Worker 或独立存储节点；
- PWA/移动端体验；
- 经独立架构评审后的低延迟实时方案。

## 10. 风险登记

| 风险 | 影响 | 当前证据 | 应对 |
|---|---|---|---|
| RKNN/NPU 驱动不可中断卡死 | 全部 NPU 任务停止 | 3 MP 在 tile 211 卡死 | 限制输入、心跳、分批重建、驱动评估、人工重启流程 |
| 插帧模型含不支持算子 | 视频路线阻塞 | 尚未转换验证 | 两个候选、固定 shape、先做算子预检 |
| 视频临时文件耗尽磁盘 | 服务不可用/数据损坏 | 视频尚未预算 | 入队前估算、任务配额、失败清理、保留空间 |
| 多用户任务泄露 | 严重隐私问题 | 当前无 owner 字段 | 公网视频前完成身份验证和所有权过滤 |
| Cloudflare 配置误改 | 公网中断或暴露源站 | Tunnel 正常运行 | 配置备份、最小权限、回滚检查，不开放 8080 |
| 模型“幻觉式修复” | 用户误认为恢复真实细节 | 生成模型固有风险 | 能力说明、原图对比、可独立关闭生成步骤 |
| 视频切镜/遮挡重影 | 输出不可用 | 插帧固有难点 | 场景检测、质量集、必要时复制帧 |
| 音画不同步 | 输出无法使用 | 尚未实现视频 | 基于时间戳 mux、ffprobe 前后校验 |
| 数据库升级损坏历史 | 任务丢失 | 当前无正式迁移 | 迁移版本、部署前备份、恢复测试 |
| 依赖/模型许可证不兼容 | 无法合法分发 | 新模型未选 | 下载前审查并记录许可，不提交受限权重 |
| 任务无限排队或滥用 | 服务对合法用户不可用 | 当前缺限流 | 身份额度、全局队列上限、429/503 |
| 自动重启循环 | 加剧故障并损伤可用性 | systemd Restart=always | 区分 API 重启与整板重启，限制重试并告警 |

## 11. Definition of Done

任何功能只有同时满足以下条件才可标记 `DONE`：

- 需求 ID、范围和非目标明确；
- 实现不越过项目文件边界；
- 自动化测试和目标板集成测试通过；
- 正常、超限、非法输入、取消和失败路径均验证；
- 性能、内存、磁盘、温度和输出参数有报告；
- 用户界面和 API 错误不泄露内部路径、命令或 traceback；
- 部署脚本幂等，重复执行不会产生重复服务或重复配置；
- 有升级、回滚和清理方式；
- README/状态表/运维文档同步更新；
- Git 提交清晰并推送，工作区回到 `main...origin/main`；
- 不依赖一次性的手工改板才能重现。

研究任务的 `DONE` 表示给出了有证据的 Go/No-Go 结论，不代表功能已经上线。
